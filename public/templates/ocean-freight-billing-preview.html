🔍 Audit Report — other issues spotted while building

⚠ Issues to fix

  • Existing `ShippingModule.jsx > printDebitNote()` is a plain HTML table — far below the洋宝宝 template quality. Needs full rewrite.
  • 洋宝宝 stamp + bank info hardcoded in old templates. Must be data-driven via `issuing_company`.
  • `shipping_plans` missing `edi_fee` column — currently no place to store EDI charge.
  • `port_surcharge_total` (2,621) doesn't match sum of fee columns (1,775) on row id=216. Either trailing fees missing or `_total` is stale. Need reconciliation.
  • `tlx_fee` DB name is ambiguous — Chinese template says 「电子装箱费」 but tlx = telex release. Rename + clarify.
  • Fee responsibility (seller vs buyer) is NOT stored anywhere — currently we'd have to derive from incoterm on every render. Consider `raw.charge_responsibility` map.

📋 To clarify with you

  • FOB split: do we generate TWO PDFs (seller copy + buyer copy) or ONE PDF with both halves visible to internal?
  • CNF/DDP "Suggested Customer Quote" — show factory the margin or hide? Currently shown.
  • Simple vs Full: is this a per-customer setting (`customers.raw.debitNoteStyle`) or per-document toggle?
  • Stamp image: do we want real PNG seal upload per `issuing_company`, or text placeholder OK for now?
  • Bank info section — confirm structure: Bank/Swift/USD A/C/CNY A/C/Account Name. Or 6 fields per currency?
  • EXW for customer includes 拖车费 — is this customer-arranged trucking or seller-arranged?

✅ Locked rules (applied to all templates above)

  • NO `company_code` rendered anywhere customer-facing — only `company_name_en` + country.
  • FROM block removed on FI; TO/收件方 enlarged to 18px bold.
  • Bank info hidden behind placeholder until data model finalized.
  • Issuing company (洋宝宝/巴匕/etc) treated as a variable — JSX must read from `issuing_company` config, not hardcode.
  • Stamp shape kept generic (公章/业务章) — swappable per issuer.
  • FQ shows 业务章 (sales seal), FI shows 公章 (financial seal) — different stamps.
  • Single body component, multiple shell wrappers. No fork.
