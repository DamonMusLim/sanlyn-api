🔑 核心原则（落地前必须钉死）

  • 1. S 签章 = 物理强制。document.shipper_id == current_user.company_id 才能上传，DAS 模板锁住公司抬头字段不可改。Sanlyn 居间人就算是 admin 也不能签 — fail-closed。
  • 2. 司机最小可见集。司机视角 = 1 个节点（拖车）。客户名/价格/利润/其他订单 = data-hidden-for="driver"。永远不见，前端一查 role 就过滤。
  • 3. 报关行只见报关相关。能看 IV/PL/SC + 报关底稿 + 装柜数据（柜号/封号/重量），看不见客户名/利润/拖车细节/内部备注。
  • 4. AI 生成默认可改。报关底稿/检疫底稿是 AI 草拟，工厂/贸易/报关行三方都 V+E（点开可改），任何一方改都进操作日志。
  • 5. BL 草稿三方核对。Sanlyn / 工厂 / 贸易 三方 V+E，谁先确认谁先冻结，最后船司签发后变成 V-only。
  • 6. 讨论分频道权限隔离。司机看不见报关频道，报关看不见拖车频道，客户看不见工厂频道，Sanlyn 全见 + 内部专属频道。
  • 7. 财务硬隔离。客户付款仅 Sanlyn / 贸易 / 客户三方可见。工厂/报关/司机/货代/保险均不可见 — 防跳单。
  • 8. 模板防串台。SHIPPER 抬头字段从 order.shipper_id 锁定写入，下载时已固化，不允许在客户端改。

📋 落地清单（按这个矩阵打代码）

  • 后端：permissions(role, doc_type, action) → bool 一个查询函数 + 数据表 permission_matrix 映射上面的 V/E/U/S。
  • 前端：<CanI action="upload" doc="telex_log"> 包装组件，按角色出按钮 / 隐藏区块。
  • API：每个写操作必须先校验 shipper_id + action，fail-closed。
  • 讨论频道：discussion_messages.channel 字段 + 频道权限表 — 不写到消息体内的 metadata。
  • UI 视图：报关行端 = 简化版（只 4 节点：报关底稿 / 报关委托书 / 正本报关单 / 报关频道讨论）；司机端 = 1 节点 + 1 频道；其他角色按矩阵渲染。
