设计逻辑（你之前的正本设计）

  • §1 待我报价 — Sanlyn 派给我的常规 RFQ。我提交我的报价后,Sanlyn 后台跟其他几家比较选标。我看到 "已 N 家在报" 的数字但不见别人的价(防跳单核心)
  • §2 已提交 — 等待 Sanlyn 选标。状态有 "待选标 / N 家在报 / 未中标"
  • §3 已中标 — 进入履约 → 跟 SO-XXXX 关联
  • §4 ⭐ 立即抢单 — 核心创新:Sanlyn 给的紧急询价,第一个 ≤ 参考底价的报价直接自动成交(不用等选标)

为什么"立即抢单"是关键

  • 👍 货代有动力主动抢 — 比常规报价快 N 倍
  • 👍 Sanlyn 紧急情况秒成交 — 不用等几小时选标
  • 👍 只显示参考底价(Sanlyn 接受的最高价),不显示别人的实际报价 — 防跳单底线
  • 👍 在抢的家数(社交压力)是公开的,但具体多少不公开

看不到的(铁律)

  • ✗ 其他货代的实际报价
  • ✗ 客户名 (永远 *****)
  • ✗ Sanlyn 加价多少 / 客户成交价
  • ✗ 其他报关行 / 车队 / DDP 价格
  • ✗ 跨服务线信息(我是海运 → 看不到报关 / DDP / 保险)

跟 admin Pricing-V2 Hub 对比
